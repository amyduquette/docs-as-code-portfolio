# Documentation workflows

These samples show three documentation workflows I created and maintained with engineering input and AI assistance. Company details have been replaced with generic examples.

[Documentation operations](../docs-standards/DOCS_OPERATIONS.md) shows how these implementations fit into the broader documentation program and distinguishes active systems from planned work.

| Workflow | Purpose |
| --- | --- |
| [Link checker](link-checker/README.md) | Checks internal routes, anchors, assets, redirects, and navigation. |
| [Reader-signal digest](reader-signal-digest/README.md) | Uses sanitized documentation analytics to identify topics that may need attention. |
| [Weekly docs changelog](weekly-docs-changelog/README.md) | Turns merged documentation pull requests into a reader-focused weekly update. |

The original workflows ran through GitHub Actions. The copies here are disconnected work samples. Their workflow files are included as examples, and no credentials or hosted integrations are configured in this repository.

Automated code-to-docs drift detection is not included because it was planned rather than implemented.
